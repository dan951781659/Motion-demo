训练准备 + 管理后台方案

会议修订 V5 · 2026-11-07 · 已确认并落入 Demo 依据动作库表《动作库-内部》第一期 191 条有内容动作。本版改为：模板内选动作、完全自定义内容、引导视频、发布机制、设备端床体引导，并补全每个字段的用途 / 影响 / 数据流。

结论速览

  1. 训练准备页完全由安装方案模板驱动：可选 1 个引导视频 + 1～5 张自定义卡片（图片 / 主标题 / 副标题）+ 顶部标签。不再固定「放凳子 / 换配件 / 调卡扣」三张；位置只用文字（如「与肩同高」）或龙门架档位，不出现厘米数，也不按身高换算。
  2. 安装方案模板是唯一维护入口，所有与安装方案相关的信息都在「安装方案模板」一张表里看完：点「已加入动作」数量跳到动作库并按该模板筛选，点「待确认」数量展开待确认动作，点序号「›」展开语言行；表尾有「未归属动作」。动作库页面回到线上原样，只多一个「安装方案」筛选项。
  3. 选动作流程：建模板时填「适用场景 / 动作属性 / 训练部位 / 配件」（均多选，不选＝不限）→ 系统自动筛出候选动作 → 人工勾选要加入的。成员关系是明确保存的；设备端只读成员。一个动作只属于一个模板，没有优先级和冲突计算。
  4. 发布才生效：模板状态「未发布 / 已发布 / 有未发布修改 / 待删除」。设备端只读已发布版本。条件字段不下发，改条件无需发布。每个模板单独发布，核对变更后再确认，没有「发布全部修改」。所有新增 / 修改 / 成员变化 / 启停 / 翻译 / 删除 / 发布都进操作日志。
  5. 翻译交互统一为动作库样式：动作库管理、安装方案模板、AI动作列表三处都用「选择翻译语言」弹窗 → 序号列「(n)」→ 每种语言一行（语言列 + 状态）。语言行可独立编辑、上架、下架、删除，上架后设备端才使用；视频不翻译；草稿、下架或缺译文回退中文。
  6. 床体引导只在设备端：目标动作场景与床体状态不符时（力量 → 普拉提且床未展开锁定；普拉提 → 力量且床未收起），设备自动弹引导页，复用现有「床体控制」流程。系统固定逻辑，管理后台不配置、不发布、不翻译、不记日志。
  7. 推荐配重保持线上单值字段，不改三档，Demo 不展示建议重量（不同性别和人群承重不同，避免因推荐重量导致拉伤的责任风险）。
  8. AI 动作 = 有 SO 库 ID。so 库给默认纠错类型（常见 4 项），特殊动作可增加类型，同一类型多条文案；屏幕文案和录音分开维护。不做通用库。

1. 设备端训练准备页

目的

现有动作详情页的安装示意不够醒目，用户开练时会忽略换配件或调卡扣。准备页把它拉进主流程，并用一个短视频把「先调龙门架高度、再换成手柄」这类连续操作一次讲清楚，文字步骤清单保留。

一页结构

标题 + 标签动作名 + 模板顶部标签（可选）
→
引导视频（可选）16:9，循环、静音；失败显示封面
→
1～5 张文字步骤卡图片 + 主标题 + 副标题
→
已完成，查看动作通栏主按钮，进入动作详情

何时出现

情况准备页
动作属于一个已发布且启用的模板，且与上一个动作不是同一模板展示该模板的视频 + 卡片
相邻两个动作属于同一模板不弹
动作未归属任何模板 / 模板停用 / 模板未发布不出现，直接进动作详情
视频未下载完 / 加载失败 / 离线无缓存视频区显示封面图，文字与按钮照常，不阻断训练

注：普拉提动作是否需要准备页，取决于运营是否为其建了模板（如「放置箱体」）；没建就直接进动作详情。普拉提床的展开 / 收起由下面的「床体引导」负责。

2. 安装方案模板

一条模板 = 模板名 + 启用开关 + 引导视频（可选）+ 1～5 张自定义卡片 + 顶部标签 + 条件字段（适用场景 / 动作属性 / 训练部位 / 配件，仅用于筛候选）+ 成员动作 + 翻译。模板不含适用型号：动作本身已有适用型号，天然归属。

创建流程

  1. 填训练准备内容：视频（可选）、卡片、标签。预设只是「快捷添加」文案，可随意改。
  2. 填条件字段（全部多选，不选＝不限）。配件取自「器械管理」。
  3. 系统筛出候选：必须是「视频动作 / 非视频动作」（片头 / 片尾等不参与），且满足所有已填字段（字段内多选＝满足其一，字段之间＝同时满足）。
  4. 人工勾选要加入的动作。已在其他模板里的动作会提示，勾选后将从原模板移到本模板。
  5. 保存草稿或发布。

成员与归属

  • 待确认：满足本模板条件、但还没归属任何模板的动作，仅提醒，不自动加入。
  • 未归属动作：符合条件资格、但不在任何模板里的动作，列在表尾一行，点开可批量处理。
  • 动作被删除时自动从成员里移除；动作下架时设备端不会出现，但仍保留成员关系。

列表页

单张主表 + 筛选标签：模板名、状态、条件、成员数、待确认数、语言、更新人、操作。点行展开：成员动作、待确认动作、语言。

3. 动作库哪些字段有变化

本期动作库只新增一个筛选项「安装方案」（从模板列表点「已加入动作」数量跳转时自动带上），其余字段、选项、顺序、操作与线上 motionstation.visbodyfit.com/#/action 完全一致。「适用场景 / 动作属性 / 训练部位」是已有字段，只是在安装方案模板里被拿来筛候选动作；「安装示意」仍只给动作详情页使用，与训练准备页互不覆盖。推荐配重保持线上单值字段。

4. 发布与生效

状态含义设备端
未发布新建后从未发布看不到
已发布当前草稿 = 已发布版本读取已发布内容
有未发布修改草稿与已发布版本不同仍读旧的已发布版本
待删除已标记删除，发布后下线发布前仍显示
  • 进入发布快照的内容：模板名、启用、成员动作、标签、视频、卡片、已上架语言的译文。语言行的上架 / 下架对已发布的模板立即同步，未发布的模板等发布后生效。条件字段不进快照，改条件无需发布。
  • 每个模板单独发布，弹窗列出该模板的变更项。导入的模板要逐条核对后再发布，没有「发布全部修改」。
  • 操作日志记录：新增 / 修改 / 成员变化 / 启用 / 停用 / 翻译 / 删除 / 发布，含操作人与时间。

5. 床体引导（仅设备端）

切换方向触发条件引导
力量训练 → 普拉提床体不是「已展开并锁定」请展开普拉提床
普拉提 → 力量训练床体不是「已收起」请收起普拉提床
同一场景内切换—不触发
  • 由设备按「目标动作的适用场景 + 当前床体状态」自动判断；动作自带场景，无需运营配置。
  • 主按钮进入现有「床体控制」的展开 / 收起流程；不想现在处理可返回，不会开始训练。完成后回到引导页，再继续进入训练准备。
  • 文案是设备端固定的 UI 文案（随设备语言包），不经管理后台发布，也不进后台操作日志。

6. 推荐配重

保持线上「动作库 → 推荐配重」单值字段，本期不改。不新增「建议重量」，设备端训练准备页也不展示任何建议重量。原因：不同性别和人群承受重量差异很大，按推荐重量训练若造成拉伤，责任无法承担。

9. 新模板上线初始化

  1. 先按「适用场景 / 动作属性 / 训练部位 / 配件」建第一批模板，系统筛出候选，人工勾选成员。模板较多时，用列表「批量导入」按 CSV 一次写入草稿（一行一个模板；错误行跳过；视频和图片导入后再到编辑页上传）。
  2. 看列表表尾「未归属动作」与各模板「待确认」，逐步补全。
  3. 录制并上传引导视频（可选），补卡片图片与翻译。
  4. 单个或批量「发布」，设备端同步后生效。

10. 待确认

  • 卡片副标题（卡片主标题下方的灰色说明文字）是否用语音合成朗读：待确认。
  • 发布粒度：是否需要「定时发布」「回滚到上一版」：待确认。
  • AI 动作纠错文案的发布时机，是否也走同一套发布机制：待确认。
  • 设备端同步与缓存策略（同步频率、视频预下载时机、存储上限）：待确认。

11. AI 动作纠错文案

口径

有 SO 库 ID 就是 AI 动作。表中 127 个，其中 44 个已有终版屏幕文案。

结构：按动作配置，不锁死 4 条

so 库给该动作一组默认纠错类型（多数是下面 4 项），后台用稳定 key 存，不用 1/2/3/4 序号。这是起点，不是上限。

常见默认 key中文说明
rom幅度动作是否做到位
symmetry左右对称两侧是否同步
stability稳定性核心 / 站位 / 关节稳定
tempo节奏速度是否过慢或停顿
  • 特殊动作可再增加一种类型（例如深蹲加「膝关节」）。自定义类型归该动作，不进通用库。
  • 同一类型下可多条文案，对应不同触发。例如幅度拆成「过浅 / 过深」两条，而不是挤在一句里。
  • so 默认类型不能删，以免和算法对不上；可以在下面加条。本动作新增的类型可以删。
  • so 库升级时对比清单：新增类型标「待配置」，下线类型标「已下线」。

Demo 用「哑铃深蹲」示范：幅度 2 条（过浅 / 过深）+ 本动作新增「膝关节」。

文案和语音分开

语音是自己录的，不从文案 TTS 生成。每一条文案都有独立的「上传语音 / 替换 / 删除 / 试听」。

项规则
屏幕文案中文 ≤ 32 等效字、最多 2 行。其他语言按两行内放得下提示，不硬拦。
语音文件按「动作 × 语言 × 类型 × 第 N 条」各传一条录音。无语音则只出字幕，不播报。
读取顺序当前语言 → 英文 → 中文 → 系统兜底「请查看动作示范并调整姿势」（兜底也要 32 语）。无对应语音则静音。

多语言（沿用动作库）

  • 列表默认显示一种语言的内容。
  • 点「翻译」→「选择翻译语言」弹窗（与动作库一致）→ 按中文的类型结构和条数生成所选语言（草稿），ID 列出现「(n)」，展开为语言行；各语言单独上架。
  • 点进某一语言 → 改该语言的各条文案，并逐条上传该语言录音。

不做通用库

每个动作独立维护类型、文案和录音。相同源文案的译文在后台内部自动复用，运营不可见。同一句话要改时，用「按文案查找替换」，替换前显示影响条数。

批量导入

  1. 导出模板：按每个动作实际的类型 × 条数预填，不强制 4 列。语音文件名可附在表里对照，但录音仍在详情页逐条上传。
  2. 导入时校验字数、缺项、未知 key，给出错误报告。
  3. 导入后再点翻译，按语言校对、上传语音。
  4. 现有 44 个动作的终版文案可按此模板先导入。
